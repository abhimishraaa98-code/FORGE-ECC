A connected engineering workflow

From codebase discovery to confident changes.

FORGE brings practical engineering signals into one workflow. Each analysis is inspectable, and recommendations stay separate from actions.

01

Codebase intelligence

Inspect project structure, languages, manifests, frameworks, dependencies and scripts before planning work.

02

Architecture mapping

Explore source modules, imports, symbols, circular relationships and likely downstream impact.

03

Change risk analysis

Connect working-tree changes with structural hotspots, quality signals and candidate tests.

04

Review intelligence

Save review snapshots, compare findings over time and validate proposed patches without applying them.

05

Verification history

Run explicitly selected project scripts and record outcomes, durations and regression signals.

06

Engineering dashboard

Bring project health, architecture, saved runs, reviews and workspace exploration into one local control center.

How FORGE thinks

Four stages. One accountable loop.

Keep context, plans, execution and verification connected without hiding the evidence.

01 / UNDERSTAND

Inspect the project

Discover the stack, structure, dependencies and existing engineering signals.

02 / MAP

Trace relationships

Explore architecture, symbols, likely impact and relevant test candidates.

03 / PLAN

Review the proposal

Organize tasks and AI-generated suggestions behind explicit approval boundaries.

04 / VERIFY

Check the outcome

Run selected checks, save evidence and compare results with prior runs.

Built around developer control

Useful intelligence. No invisible actions.

Local-first by design

  • Project inspection runs against a workspace you choose.
  • Dashboard binds to the local machine by default.
  • Saved history stays in the project's local .forge directory.
  • AI review only sends selected source context to your configured provider.

Human approval stays explicit

  • Discovery does not execute project scripts.
  • Verification requires you to select a named script.
  • Patch proposals are validated as dry runs, never silently applied.
  • Risk scores and architecture findings are advisory, not guarantees.
