Developer control

Transparent by default. No mystery automation.

Local-first workflow

  • Analyze a project directory you choose.
  • Dashboard binds to localhost by default.
  • Saved snapshots and histories stay in the local .forge directory.
  • AI review is optional and sends selected source context to your configured provider.
  • Public site previews do not access your local source code.

Human approval stays explicit

  • Discovery does not automatically execute project scripts.
  • Verification requires you to select a named script.
  • Patch checks are dry runs; they do not apply changes.
  • Dependency remediation is a plan, not an automatic installer.
  • Risk scores are heuristics, not security guarantees or defect predictions.

Questions

Know what you're getting.

Is the public website the actual engineering dashboard?

No. The public website explains FORGE and contains illustrative previews. The full engineering dashboard runs locally against a project you select.

Does FORGE automatically change my code?

No. Patch validation is a dry run. Remediation output is a plan. Verification runs only when you select a named script.

Does FORGE scan every programming language?

Current architecture and deep AST analysis focus on JavaScript and TypeScript. Other project signals are based on recognized manifests, files and configuration.

Does the health score prove a project is secure?

No. It is an evidence-based prioritization heuristic. Missing audit reports are marked not assessed, and a score is not a certification.

Does AI review send my code somewhere?

AI review sends selected source excerpts to the provider you configure. Review your provider's data handling terms before enabling it.

Can I use FORGE without a hosted account?

The CLI and engineering dashboard are local tools. The public Vercel site is a separate static product page.
